100 Art Styles — Plan v2

A revision of art-styles-plan.html. The original file is not changed. Status: plan only. No code is written and no style in this file was rendered. Date: 2026-11-13. Phase 0 done on 2026-11-13: the owner answered the 7 decisions (section 7) and the list was edited (section 4b).

0. Review of the original plan

The structure of the original plan is correct and stays: animation = scene + art style, the art style is a post shader with no topic, 5 phases, a pilot before the 100. The weak part is the draft list. It has four defects.

  1. The entries are names only. A name such as "tempera" does not say what the frame shows or how it moves. The owner cannot judge the list.
  2. Many entries give the same picture as a filter. Examples: gouache, tempera and fresco; sepia, daguerreotype and tintype; cross-stitch and needlepoint; halftone newsprint, comic book dots and manga screentone; tile mosaic and Byzantine mosaic; 8-bit, 16-bit, 4-shade green and 4-colour PC palette. The plan's own Phase 4 pixel-difference check would flag these pairs.
  3. One entry repeats the first set. The plan says the draft does not repeat the existing styles. "Ukiyo-e print" repeats style 46, Woodblock Print.
  4. Most entries are filters on a finished picture. A filter of that type does not use the two things this project has and a photo filter does not have: the 3D data (depth, surface direction) and the timeline (beats).

Count: of the 100 original entries, stay (some merged or renamed). 59 were cut in the v2 review (section 4) and 6 more in the Phase 0 list edit (section 4b).

1. The new rule for an art style

An entry goes on the list only if it does one or more of these. A flat colour change alone is not sufficient.

  • The medium changes with time. Pigment spreads and dries. A photo develops. An ink layer is pulled. The change is tied to the beats.
  • The marks follow the surface. Stroke direction comes from the surface direction. Marks are fixed to the object, so they do not slide when the camera moves.
  • The depth is the material. The depth image becomes paper sheets, a carving, porcelain thickness or a stereo pair.
  • Light or an instrument makes the picture. Thin-film colour, a stripe projector, a scanning beam.

Each style has no topic and works on any scene, as in the original plan.

Limits found in the code:
  • No memory between frames. update(t) sets the full state for t (HANDOFF section 2). A shader cannot read the frame before. Thus datamosh and feedback trails are not possible. Each time effect in the list is a function of t and the beat times only.
  • A post shader cannot tell which object is new. A beat effect ("the picture develops") applies to the full frame.
  • Labels do not write depth (HANDOFF build log, board-game note). A depth-based style sees a label as background. Section 5 proposes a separate label pass.
  • Tone mapping runs after the post shader (pencil-sketch note: multiply paper white by about 2.2). Posterize in gamma space (woodblock note).

2. The list: 100 art styles in 10 groups

Each row says what the frame shows and how the medium moves. keep = from the original draft (possibly merged or renamed). new = not in the original draft. ver = an art-style version of a first-set style (decision 1); the source id is in the tag column. Generic names only.

Inputs (expected, not tested): C colour image, D depth, N surface direction. These three exist in the kit today. W world position, B beat times, S frame step, M material change, X renders at earlier times. These five need the kit changes in section 5.

Version check (15 ver rows): compare each version on a new scene with its source style in the first set. This check is the reverse of the others: the version must give the same look, so a large difference in look is a fail. The scene content is different by design.

Hard cases

  • Autostereogram (29): labels cannot be read, and some viewers cannot see the effect. It is a deliberate special case. The shader needs a loop of about 30 texture reads for each pixel. Decision 7: keep it, with a note on its card.
  • Event camera (49), Motion echoes (92), Long exposure (100): input X. Each frame needs 2 to 16 scene renders, so live play is slower by about that factor. stage.js:322-335 already averages sub-frames at offset times with a short shutter; long exposure is that loop with a 1-second shutter. See decision 6.
  • Faceted multi-view (91): the original plan expected several cameras. This version shifts each facet with the depth image, with one camera. It gives a small change of view point only, and it leaves gaps at depth steps.
  • Quilling (67), Mosaic (74), Flow-field strokes (20): the marks must follow edges over a distance. A shader does this with many texture reads. Expect slow frames in headless Chrome with software rendering.
  • One-bit dither (62), with its 16-colour option: the original plan asked for a low-size render in the kit. A shader can read the colour image at the centre of each large pixel instead. No kit change, if the result is clean.

Reserve

If a style drops out, replace it from this list (all from the original draft): Islamic tile geometry, film noir, teletext, tissue paper, Art Nouveau. Two more, not from the original draft: mechanical television (30 curved scan lines in orange light), solarised print (partly reversed tones).

Weakest entries

The v2 review named 8 rows with input C only and 3 pairs with one mechanism. The Phase 0 list edit cut all 8 rows and one row of each pair (section 4b). No row now has input C only.

2 new pairs use one mechanism with a different surface. Phase 4 must compare them: Stained glass (36) and Cloisonné (77), cells with an outline; Corona discharge (40) and Vector scope (45), glowing lines at the edges.

3. Not possible, with the reason

  • Datamosh and feedback trails: each needs the frame before. See section 1. Long exposure and the event camera are different: they need a render at a different time, which is deterministic. They are in the list with input X.
  • Slit-scan (a different time in each column): needs one scene render for each strip. The existing style time-slice does this inside its own file with 24 renders. As a kit function it has 1 user.
  • Low-res early-3D jitter: the jitter is in the vertex positions. It needs a patch to each material's vertex shader, not a post shader.
