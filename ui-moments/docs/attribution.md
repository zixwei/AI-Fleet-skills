# 参考与署名

做界面难免参考别人。想法不受版权保护，借鉴想法、自己写代码完全可以；受保护的是别人的代码、图片、字体和具体的视觉表达。

## 什么时候需要标注

| 情况 | 要不要标注 | 怎么做 |
| --- | --- | --- |
| 通用交互模式（开关、步进器、长按确认、骨架屏……） | 不需要 | — |
| 明显受某一个具体作品启发（看到某条帖子、某个演示才想到） | 建议标注 | 在 `gallery/works.js` 写一行 `credit`，卡片会自动显示 |
| 使用了别人的代码、SVG、图片、字体 | 必须 | 只用有开源许可的，原样放进 `vendor/`，更新 CREDITS.md 与 THIRD_PARTY_NOTICES.md |
| 做出来和某个作品几乎一样 | 不发布 | 改造型，或先征得原作者同意 |

参考来源随作品标注即可，不需要在 CREDITS.md 维护清单。

## 每个作品都要写

如果作品有独立目录，README 里写明：

- **灵感来源**：原作者，以及原帖、原仓库或原网页的链接。
- **借鉴了什么**：比如交互方式、构图、某个动效。
- **我们补充或改动了什么**：如实说明工程接入、交互扩展或重新实现；完整集成不必虚构原创改进。
- **第三方代码和资源**：名称、链接、许可证。

画廊卡片标注「原创」「开源集成」或「参考后实现」。开源集成同时显示上游库名，详情保留作者、来源与许可。只参考展示形式时，在详情说明参考来源，按实际图形、动效和代码的来源标注。

## 什么能直接用

- **有开源许可证的代码和资源**（如 MIT、Apache 2.0、OFL）：可以使用，按许可证要求保留版权声明和许可证文本；Apache 2.0 还要注明修改过的文件。
- **没有许可证的作品**（推文、截图、视频、网页）：只借鉴想法，代码和素材全部自己写、自己画。
- **有分发限制的模板**：访问权限和成品使用权以原作者条款为准。公开仓库、发布包和导出内容只收录允许公开分发的文件。
- **以下内容不放进仓库**：
  - 苹果的 SF 字体、SF Symbols 和 HIG 原文（不是开源的）。
  - Shopify Polaris 的代码（许可证带有使用限制）。
  - Salesforce 的图标和图片（CC BY-ND，不允许修改）。
  - 任何公司的商标和 Logo。也不暗示得到了对方认可。

## 太像就不发

如果作品和原作几乎一样，只是换了实现方式，就不发布，或者先征得原作者同意。

## 已授权开源实现的完整集成

对于明确允许复制、修改、分发的开源实现，可以完整集成；此类集成不适用上面对未获代码复用授权的外观复刻的限制。须明确标为「原作 / 完整集成」，保留完整上游许可证，记录原仓库、版本和实际改动，不宣称第三方动效由我们原创。LDRS 与 Loading UI 均按完整集成保留原作者与原始许可，详见根目录 `THIRD_PARTY_NOTICES.md`。

## 条目来源类型

- 原创实验：自行构思并实现，可使用AI辅助开发；不以工具是否由AI生成来替代来源判断。
- 开源完整集成：明确标注上游库和作者，保留原文件、固定版本／提交与完整许可证；我们的贡献说明为整合、预览和使用体验。
- 参考后重新实现或基于提供内容扩展：说明参考对象、实际取用的内容和本站新增部分，不将参考来源笼统改称原创。
